## Defect found and fixed
The original driver assignment logic required the driver to be ONLINE on every assignment. After the first assignment, the driver becomes BUSY, so a second order could not be assigned even though the business rule allows up to five active delivery locations per trip.

Correction:
- Reuse an existing active trip for additional orders.
- BUSY driver with an active trip remains eligible.
- Synchronize drivers.active_trip_id to the active trip.
- Preserve the maximum-five active-stop limit.
- Offline drivers remain rejected.
