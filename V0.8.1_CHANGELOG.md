# V0.8.1 — Foundation Hardening

## Tujuan
Memperkuat pemisahan role dan alur status order sebelum membuka V0.9.

## Perubahan
- Customer yang mencoba `/dashboard` diarahkan kembali ke halaman customer, bukan area staff.
- Dashboard staff dibuat role-aware: Admin/Owner melihat fungsi administrasi; Kasir hanya melihat cross-check order; Kitchen hanya melihat queue produksi; Driver hanya melihat delivery.
- Kasir hanya dapat melakukan `pending_payment -> confirmed` dan hanya jika pembayaran sudah `paid`.
- Kitchen hanya dapat melakukan `confirmed -> processing -> ready`.
- Admin/Owner mengikuti state transition yang valid dan tidak dapat mengubah status mundur.
- Tombol aksi di dashboard disesuaikan dengan role dan status order.
- Output nama/alamat/order pada dashboard di-escape sebelum dimasukkan ke HTML untuk mengurangi risiko XSS pada UI.
- Audit log status menyimpan transition, misalnya `confirmed->processing`.

## Belum dikerjakan
- Promo engine lengkap
- Dine-In QR
- POS walk-in
- Payment gateway nyata
- GPS browser / geocoding production
- Central sales integration lintas channel
- Production security hardening penuh (CSRF, rate limiting, secret management, dll.)

## Validasi
- Python syntax check (`py_compile`) berhasil.
- Runtime integration test membutuhkan environment dengan Flask dependencies terpasang. Environment audit saat ini tidak memiliki akses package index, sehingga runtime test dilakukan oleh user di PC yang sudah menjalankan V0.8.
